# じゃんけん大会シミュレーター

## 学習ポイント
配列/コレクション、複数オブジェクトの管理

## 概要
複数プレイヤーのじゃんけんトーナメントを実施する対話式CLIツール。`register <名前...>`で参加者を
登録し(登録のたびに現在の登録人数を表示)、`start`でシングルエリミネーション方式の大会を実施して
各ラウンドの対戦経過と優勝者を表示する。`exit`で終了する。

## 実装メモ
- `Tournament`のコンストラクタは参加人数が2人以上であることのみを検証する。当初は「2のべき乗」を要求していたが、参加人数が奇数のラウンドでは最後の1人を不戦勝として次ラウンドに進める(`playRoundWithResults`)ことで、2のべき乗でない人数の大会にも対応できるようにした。
- `playRound`は`List<Player>`を先頭から2件ずつインデックスでペアリングし、勝者だけを次ラウンド用の新しい`List`に集めていく。複数のPlayerオブジェクトをコレクションで管理しながら、ラウンドを重ねるごとに絞り込んでいく流れを1メソッドに凝縮した。内部的には対戦カード・勝者を`MatchResult`(record)として返す`playRoundWithResults`に委譲しており、`playRound`は勝者リストのみを取り出す薄いラッパーになっている。
- あいこの場合は`handSupplier`(手を決定する関数)を再度呼び出して決着まで再戦する`while`ループを実装しているが、再戦回数に上限(`MAX_REROLLS = 1000`)を設けている。決定的に引き分けの手だけを返す`handSupplier`(テスト用スタブや、将来「常にグーを出す戦略AI」等)を渡すと無限ループしてしまうため。
- `runTournament`は`playRound`を参加者が1人になるまで繰り返すだけのシンプルな実装だが、02_RockPaperScissorsの1対1対戦ロジックを「複数人・複数ラウンド」に拡張した集大成という位置づけ。ラウンドごとの対戦結果を通知するコールバック(`Consumer<List<MatchResult>>`)を受け取るオーバーロードも用意し、優勝者だけでなく大会の進行を`Main`側で表示できるようにした。
- `Player`に名前ベースの`equals`/`hashCode`を追加し、`Main`の`register`で同名プレイヤーの重複登録を`IllegalArgumentException`で拒否するようにした。
- `Main`は01〜07と同じ設計パターンで、プレイヤーの手を`Function<Player, Hand>`として注入可能にし、`register`→`start`の一連の操作で優勝者が正しく表示されることを結合テストで検証した。`start`完了後は参加者一覧をクリアし、続けて`register`→`start`すると新しい大会として扱われるようにしている。
