== 概要

=== 目的
四則演算(`+`, `-`, `*`, `/`)とメモリ機能(M+, M-, MR, MC)を持つ、標準入出力ベースの対話式CLI電卓を提供する。
`0.6 - 0.2` のような小数演算で丸め誤差が出ないよう、内部の数値表現には `double` ではなく `BigDecimal` を用いる。

=== 主な機能
* 四則演算(`"数値 演算子 数値"` 形式の1行入力を解析して計算)
* メモリ機能(M+: メモリ加算 / M-: メモリ減算 / MR: メモリ呼び出し / MC: メモリクリア)
* 不正な入力(数値変換失敗・不正な演算子・ゼロ除算)をエラー表示し、アプリを継続する
* `exit` によるアプリ終了

== 補足事項

=== BigDecimal採用理由
`double` で `0.6 - 0.2` を計算すると `0.39999999999999997` のような誤差が発生する。本アプリは学習用電卓として厳密な小数計算を扱うため、`BigDecimal` を採用した。

=== 除算の丸め処理
`1 / 3` のような無限小数は、そのままでは `ArithmeticException` になる。本アプリではスケール10・`RoundingMode.HALF_UP` で丸めることで例外を回避しつつ、実用上十分な精度を確保している。表示時は `stripTrailingZeros()` で末尾の余分な0を除去する(例: `0.4000000000` → `0.4`)。

=== テスト方針(TDD)
Red → Green → Refactor サイクルで実装した。

* *単体テスト*(`CalculatorTest` / `CalculatorMemoryTest`): 四則演算の正常系・ゼロ除算・不正な演算子、メモリ操作(M+/M-/MR/MC)の初期値・加算・減算・クリアを検証
* *結合テスト*(`MainTest`): `Scanner`/`PrintStream` を注入した対話ループに対して、不正な数値入力時にクラッシュせず継続すること、複数コマンドの一連の入力(例: `"2 + 3"` → `"M+"` → `"10 - 4"` → `"M+"` → `"MR"`)でメモリ値が正しく積算されることを検証

=== 設計上の工夫
* `Main.run()` を `Scanner`/`PrintStream` を引数に取る静的メソッドとして分離し、`StringReader`/`ByteArrayOutputStream` を用いた結合テストを可能にしている。
* `Calculator` の演算メソッド(`add`/`subtract`/`multiply`/`divide`)は副作用を持たない純粋な計算とし、状態を持つメモリ操作(`memoryAdd` 等)と役割を分離している。
