== 概要

=== 目的
指定ディレクトリ直下のファイルを拡張子に応じたサブフォルダ(`images`/`text`/`documents`/`others`)に振り分ける対話式CLIツールを提供する。`java.nio.file` の `Path`/`Files` 操作の実践を目的とする。

=== 主な機能
* `organize <ディレクトリパス>` でディレクトリ直下のファイルを拡張子別に整理する
* `exit` によるアプリ終了

=== 開発環境
[cols="1,3", options="header"]
|===
| 項目 | 内容

| 言語
| Java 25

| ビルドツール
| Maven(フォルダ単位で独立した `pom.xml`)

| テスト
| JUnit 5(`junit-jupiter`、`@TempDir` で実ファイルシステムを使用)

| ファイル操作
| `java.nio.file.Path`/`Files`(`java.io.File` は不使用)
|===

== 補足事項

=== java.nio.fileでの統一実装
学習ポイント通り `java.io.File` ではなく `java.nio.file.Path`/`Files` で実装している。`Files.list` でディレクトリ直下のエントリのみ取得(再帰しない)、`Files.isRegularFile` でファイルのみ対象化、`Files.createDirectories` でカテゴリフォルダ作成、`Files.move` で移動、と一連の操作をすべて `Files` の静的メソッドで完結させている。

=== 拡張子によるカテゴリ判定
`FileCategorizer` は拡張子→カテゴリの `Map<String, Set<String>>` を持ち、`categoryOf` で判定する。未知の拡張子・拡張子なしのファイルはいずれも `"others"` に分類する。

=== 非再帰的な整理
`organize` はサブディレクトリを移動対象にしないことをテストで確認済み(非再帰的な設計)。`Files.list` は直下のエントリのみを返すため、既存のサブフォルダを誤って移動対象にしてしまう心配がない。

=== テスト方針(TDD)
Red → Green → Refactor サイクルで実装した。

* *単体テスト*(`FileCategorizerTest`): 拡張子ごとのカテゴリ判定、未知拡張子・拡張子なしの`"others"`分類を検証
* *結合テスト*(`FileOrganizerTest`/`MainTest`): `@TempDir` で実際のファイル・ディレクトリを作成し、`Files.exists` で移動結果を検証。モックを使わず実ファイルシステムに対してテストすることで、`java.nio.file` のAPIの挙動そのものを確認している

=== 設計上の工夫
* `Main` は01〜12と同じ設計パターンで、`Scanner`/`PrintStream` を引数に取る `run` 静的メソッドに分離している。
