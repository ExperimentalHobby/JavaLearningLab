== 概要

=== 目的
プレイヤー(標準入力)とコンピュータ(`Random`)でじゃんけんを行う対話式CLIアプリを提供する。

=== 主な機能
* 「グー」「チョキ」「パー」のいずれかを入力し、コンピュータと対戦する
* 不正な入力(上記3語以外)をエラー表示し、アプリを継続する
* `exit` によるアプリ終了

=== 開発環境
[cols="1,3", options="header"]
|===
| 項目 | 内容

| 言語
| Java 25

| ビルドツール
| Maven(フォルダ単位で独立した `pom.xml`)

| テスト
| JUnit 5(`junit-jupiter`)

| 乱数
| `java.util.Random`(コンピュータの手の抽選に使用)
|===

=== 実行方法
[source,powershell]
----
cd 02_RockPaperScissors
.\mvnw.cmd compile
.\mvnw.cmd test
.\mvnw.cmd exec:java "-Dexec.mainClass=com.javalab.rps.Main"
----

== 補足事項

=== Handへの勝敗ロジックの内包
`Hand` enum自身に `beats(Hand other)` を持たせ、グー→チョキ→パー→グーの三すくみ判定をenumに閉じ込めている。列挙順(ROCK → SCISSORS → PAPER)は `RockPaperScissorsGame.randomHand` の乱数マッピング(`Random.nextInt(3)`)にもそのまま利用される。

=== テスト方針(TDD)
Red → Green → Refactor サイクルで実装した。

* *単体テスト*: `Hand.beats` の三すくみ全パターン、`RockPaperScissorsGame.judge` の勝ち/負け/引き分け、`randomHand` の `nextInt` 戻り値マッピングを検証
* *結合テスト*(`MainTest`): 不正入力時にクラッシュせず継続すること、コンピュータの手を `Supplier<Hand>` で固定注入し正しい勝敗が表示されることを検証

=== 設計上の工夫
* `RockPaperScissorsGame.randomHand` は `Random` を引数で受け取り、テストでは `nextInt` が固定値を返す匿名サブクラスを注入することで、乱数に依存せず決定的に検証できるようにしている。
* `Main` はコンピュータの手を `Supplier<Hand>` として注入可能にし、01_Calculatorと同じ設計パターン(`Scanner`/`PrintStream` の注入による結合テスト)を踏襲している。
