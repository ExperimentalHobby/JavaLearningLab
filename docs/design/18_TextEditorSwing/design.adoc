== 概要

=== 目的
`JTextArea` でテキストを編集し、メニューバーからファイルの「開く」「保存」「名前を付けて保存」「終了」を行える簡易テキストエディタを提供する。`JTextArea`・ファイル入出力・メニューバーの実践を目的とする。

=== 主な機能
* 「開く」でファイルを選択し内容をテキストエリアに読み込む
* 「保存」で現在開いているファイルへ上書き保存する(未指定時は「名前を付けて保存」と同じ動作)
* 「名前を付けて保存」で保存先を選択して保存する
* 「終了」でウィンドウを閉じる

== 補足事項

=== テスト方針の分離
Issue #11(家計簿アプリ)と同じ方針で、テスト方針を明確に分離した。ファイルI/Oロジック(`TextFileService`)はTDDで自動テストし、`TextEditorFrame`(実際のウィンドウ・メニューバー・イベントリスナー配線)は実装後に実機で起動して手動確認した。

=== GUIに依存しないファイルI/O
`TextFileService` は `Files.readString`/`Files.writeString`(UTF-8)を使い、GUIに依存しない純粋なロジックとして `@TempDir` の実ファイルでテストした。読み込み/書き込みの失敗(存在しないファイル・存在しないディレクトリなど)は `TextFileException` に統一している。

=== メニューバーとイベント配線
`TextEditorFrame` は `JMenuBar` の「ファイル」メニューに開く/保存/名前を付けて保存/終了の `JMenuItem` をラムダの `ActionListener` で配線した。「開く」「名前を付けて保存」は `JFileChooser` でパス選択し、選択したファイル名をウィンドウタイトルに反映する。失敗時は `JOptionPane` でエラーダイアログを表示する。

=== 手動確認での検証内容
手動確認では、実際にWindows上でアプリを起動し、テキスト入力→「名前を付けて保存」でのファイル書き込み→タイトルバー更新→「開く」での再読み込みの一連の流れをスクリーンショットで検証した。ファイルシステム上でも保存内容が期待通りであることを確認済み。

=== テスト方針(TDD)
Red → Green → Refactor サイクルで実装した。

* *単体テスト*(`TextFileServiceTest`): `@TempDir` を用いた読み込み・書き込みのラウンドトリップ、存在しないファイル/ディレクトリでの失敗を検証
* *手動確認*: `TextEditorFrame` のウィンドウ表示・開く/保存/名前を付けて保存・エラーダイアログ表示を実機で確認

=== 設計上の工夫
* `Main` はSwingのイベントディスパッチスレッド(EDT)上でウィンドウ生成・表示を行うため、`SwingUtilities.invokeLater` を使用している。
