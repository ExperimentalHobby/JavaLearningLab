== 概要

=== 目的
生の `ServerSocket`/`Socket`(TCP)で動作するマルチクライアント対応チャットサーバーを提供する。`ServerSocket`/`Socket` と並行接続処理の実践を目的とする。

=== 主な機能
* サーバーは複数クライアントの同時接続を受け付ける
* 接続直後にクライアントが送るユーザー名以降、送信した各行を接続中の他クライアント全員へ `<ユーザー名>: <メッセージ>` の形式でブロードキャストする
* クライアント切断時は他クライアントへ退出通知を配信する

----

.\mvnw.cmd compile

# サーバー起動(既定ポート5000、引数で変更可)

----

| メッセージを送信する

| クライアントが切断すると、他クライアントへ「<ユーザー名>が退出しました」が配信される

| UC-4
| サーバーを停止する
| サーバープロセス終了時、全クライアント接続をクローズしスレッドプールを終了する

== 補足事項

=== 1接続1スレッドモデル
`ChatServer` は `ServerSocket.accept()` ループを専用スレッドで回し、接続ごとに `ClientHandler`(`Runnable`)を `ExecutorService`(`newCachedThreadPool`)へ投入する1接続1スレッドモデルを採用した。並行接続処理の基本形として学習ポイントに直接対応する。

=== CopyOnWriteArrayListの採用理由
接続中クライアントは `CopyOnWriteArrayList` で管理した。ブロードキャスト(読み取り・反復)の頻度が接続/切断(書き込み)より圧倒的に多い用途に適しており、`synchronized` なリストより単純にスレッドセーフな反復ができる。

=== 実ソケットでの結合テスト
テストはモックを使わず、`ChatServer` を実際にephemeralポート(`port=0`)で起動し、実際の `java.net.Socket` でクライアント接続する結合テストとした(既存Issue #13/#14と同じ「実リソースでのテスト」方針)。

=== ブロードキャスト除外の検証方法
「送信者自身にはブロードキャストされない」ことを検証するテストでは、接続クライアントを1つだけにしたうえで自分自身の発言後に短いタイムアウト(`SoTimeout`)付きで `readLine()` し、`SocketTimeoutException` が飛ぶこと(＝何も返ってこないこと)を確認する設計にした。2クライアントで「相手には届くが自分には届かない」ことを個別に確認するよりも、この方法の方がブロードキャスト除外ロジックの欠落を確実に検出できる。

=== レースコンディション回避のためのハンドシェイク
ユーザー名ハンドシェイク直後にサーバーから当該クライアント本人へ「ようこそ」メッセージを直接送るプロトコルにした。テストではこのメッセージを読むことでサーバー側の登録完了を待ち合わせ、複数クライアントの接続順とブロードキャストタイミングの競合(レースコンディション)を避けている。

=== 手動確認での検証内容
手動確認として、実際に `Main`(サーバー)と `ChatClientMain`(クライアント)を別プロセスで起動し、2クライアント間でのメッセージ相互送信・片方切断時の退出通知配信までコマンドラインから直接確認した。

=== テスト方針(TDD)
Red → Green → Refactor サイクルで実装した。

* *結合テスト*(`ChatServerTest`): 実ソケットでの複数クライアント接続、ブロードキャスト、送信者除外、退出通知を検証
* *手動確認*: `Main`/`ChatClientMain` を別プロセスで起動し、実際のメッセージ送受信・切断時の退出通知を確認
