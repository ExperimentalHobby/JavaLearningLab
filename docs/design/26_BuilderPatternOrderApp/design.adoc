== 概要

=== 目的
必須項目(顧客名・配送先住所・商品明細)とオプション項目(支払方法・ギフトラッピング・メモ)が混在する`Order`(注文)を、静的ネストクラス`Order.Builder`によるフルーエントAPIで段階的に組み立てるコンソールアプリを提供する。複雑なオブジェクト生成の設計練習(Builderパターン)を目的とする。

=== 主な機能
* `start <顧客名> <配送先住所>` による注文の開始(必須項目)
* `item <商品名> <数量> <単価>` による商品明細の追加
* `payment <方法>` / `wrap on|off` / `note <メモ>` によるオプション項目の設定(未指定時は既定値)
* `build` による注文の確定とサマリー表示
* `exit` によるアプリ終了

== 補足事項

=== 不完全なBuilderを生き残らせない設計
`Order.Builder`のコンストラクタは顧客名・配送先住所を必須項目として受け取り、空文字なら即座に`IllegalArgumentException`を送出する。これにより「必須項目が未設定のBuilderインスタンス」がそもそも生成されない状態を保証している。

=== エラー時もBuilderの内容を失わない設計
`build()`を明細0件で呼び出すと`IllegalStateException`を送出するが、`Main`側の例外捕捉ではBuilder変数を`null`にリセットしない。これにより、エラー後も同じBuilderに対して`item`等で入力を継続でき、それまでに入力した内容(支払方法・ギフトラッピング・メモなど)を失わずに再度`build`できる。

=== オプション項目の既定値設計
`paymentMethod`/`giftWrapping`/`note`はいずれもBuilderのフィールド初期値として既定値(「代金引換」/`false`/空文字)を持つ。これにより「オプション項目は指定しなくても妥当な注文が作れる」というBuilderパターンの利点を体現している。

=== テスト方針(TDD)
Red → Green → Refactor サイクルで実装した。

* *単体テスト*(`OrderBuilderTest` / `OrderItemTest`): Builderの必須項目検証・オプション項目の既定値・明細0件でのbuild失敗・小計計算を検証
* *結合テスト*(`MainTest`): `start`→`item`→`build`の一連の流れでサマリーが表示されること、`start`前の`item`使用時のエラー表示、明細なしの`build`失敗後も操作を継続し再度`build`できることを検証
