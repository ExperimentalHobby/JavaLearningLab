== 概要

=== 目的
売上レコード(商品名・カテゴリ・金額・数量)を登録し、Stream APIで集計する対話式CLIツールを提供する。map/filter/reduceやラムダ式の活用を目的とする。

=== 主な機能
* `add <商品名> <カテゴリ> <金額> <数量>` で売上レコードを登録する
* `list` で一覧・合計金額・合計数量・平均金額・最高額を表示する
* `byCategory` でカテゴリ別合計金額を表示する
* `exit` によるアプリ終了

|===

== 補足事項

=== ストリーム操作の使い分け
合計金額は `map(SalesRecord::amount).reduce(BigDecimal.ZERO, BigDecimal::add)`、合計数量は `mapToInt`+`sum` と、オブジェクト用ストリームとプリミティブ用ストリーム(`IntStream`)の使い分けを実践している。

=== グルーピングと集約の組み合わせ
カテゴリ別集計は `Collectors.groupingBy` と `Collectors.reducing` を組み合わせ、グルーピングと集約を1つのcollectで完結させている。

=== ComparatorとStreamの組み合わせ
最高額のレコード取得は `max(Comparator.comparing(SalesRecord::amount))` とラムダ式でComparatorを組み立てる形にしている。

=== 中間操作の連鎖
商品名一覧は `map`(商品名だけ抽出)→`distinct`(重複除去)→`sorted`(ソート)という中間操作の連鎖で実装している。日本語の自然順ソートはUnicodeコードポイント順になる(ひらがな→カタカナの順)ことをテストで確認している。

=== テスト方針(TDD)
Red → Green → Refactor サイクルで実装した。

* *単体テスト*(`SalesAggregatorTest`): 合計・平均・最高額・カテゴリ別集計・フィルタリング・商品名ソートを検証
* *結合テスト*(`MainTest`): `Scanner`/`PrintStream` を注入した対話ループに対して、不正な入力時の継続動作と `add`→`list` の一連の操作を検証

=== 設計上の工夫
* `Main` は01〜11と同じ設計パターンで、`Scanner`/`PrintStream` を引数に取る `run` 静的メソッドに分離している。
