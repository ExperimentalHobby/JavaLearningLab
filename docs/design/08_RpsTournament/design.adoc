== 概要

=== 目的
複数プレイヤーのじゃんけんトーナメントを実施する対話式CLIツールを提供する。シングルエリミネーション方式で優勝者を決定する。

=== 主な機能
* `register <名前...>` で参加者を登録する
* `start` でトーナメントを実施し、優勝者を表示する
* `exit` によるアプリ終了

=== 開発環境
[cols="1,3", options="header"]
|===
| 項目 | 内容

| 言語
| Java 25

| ビルドツール
| Maven(フォルダ単位で独立した `pom.xml`)

| テスト
| JUnit 5(`junit-jupiter`)

| 参加者管理
| `java.util.ArrayList<Player>`
|===

=== 実行方法
[source,powershell]
----
cd 08_RpsTournament
.\mvnw.cmd compile
.\mvnw.cmd test
.\mvnw.cmd exec:java "-Dexec.mainClass=com.javalab.rpstournament.Main"
----

== 補足事項

=== トーナメント人数の検証
`Tournament` のコンストラクタで参加人数が2以上かつ2のべき乗であることを検証している。トーナメント表を組むには各ラウンドで人数がちょうど半分になる必要があるため。

=== ラウンドごとの絞り込み
`playRound` は `List<Player>` を先頭から2件ずつインデックスでペアリングし、勝者だけを次ラウンド用の新しい `List` に集めていく。複数の `Player` オブジェクトをコレクションで管理しながら、ラウンドを重ねるごとに絞り込んでいく流れを1メソッドに凝縮している。

=== あいこの再戦
あいこの場合は `handSupplier`(手を決定する関数)を再度呼び出して決着まで再戦する `while` ループを実装している。本番では `Random` ベースなので毎回結果が変わり得るが、テストでは `Deque` から手を順番に取り出す関数を注入することで再戦ロジックを決定的に検証している。

=== テスト方針(TDD)
Red → Green → Refactor サイクルで実装した。

* *単体テスト*: `Tournament` の人数検証、`playRound` のペアリングと再戦ロジック、`RockPaperScissors.playMatch` の勝敗判定を検証
* *結合テスト*(`MainTest`): `Scanner`/`PrintStream`/`Function<Player, Hand>` を注入した対話ループに対して、`register`→`start` の一連の操作で優勝者が正しく表示されることを検証

=== 設計上の工夫
* `runTournament` は `playRound` を参加者が1人になるまで繰り返すだけのシンプルな実装だが、02_RockPaperScissorsの1対1対戦ロジックを「複数人・複数ラウンド」に拡張した集大成という位置づけ。
* `Main` は01〜07と同じ設計パターンで、プレイヤーの手を `Function<Player, Hand>` として注入可能にしている。
