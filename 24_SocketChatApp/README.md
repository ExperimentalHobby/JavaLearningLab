# マルチスレッドチャットアプリ(Socket通信)

## 学習ポイント
ServerSocket/Socket、並行接続処理

## 概要
生の`ServerSocket`/`Socket`(TCP)で動作するマルチクライアント対応チャットサーバー。接続直後にクライアントが
送るユーザー名以降、送信した各行を接続中の他クライアント全員へ`<ユーザー名>: <メッセージ>`の形式でブロードキャストする。

- サーバー起動: `mvn exec:java -Dexec.mainClass="com.javalab.socketchat.Main"`(既定ポート5000、引数で変更可)
- クライアント起動: `mvn exec:java -Dexec.mainClass="com.javalab.socketchat.ChatClientMain"`(複数プロセスで同時接続可能)

## 実装メモ
- `ChatServer`は`ServerSocket.accept()`ループを専用スレッドで回し、接続ごとに`ClientHandler`(`Runnable`)を`ExecutorService`(`newCachedThreadPool`)へ投入する1接続1スレッドモデルを採用した。並行接続処理の基本形として学習ポイントに直接対応する。
- 接続中クライアントは`CopyOnWriteArrayList`で管理した。ブロードキャスト(読み取り・反復)の頻度が接続/切断(書き込み)より圧倒的に多い用途に適しており、`synchronized`なリストより単純にスレッドセーフな反復ができる。
- テストはモックを使わず、`ChatServer`を実際にephemeralポート(`port=0`)で起動し、実際の`java.net.Socket`でクライアント接続する結合テストとした(既存Issue #13/#14と同じ「実リソースでのテスト」方針)。
- 「送信者自身にはブロードキャストされない」ことを検証するテストでは、接続クライアントを1つだけにしたうえで自分自身の発言後に短いタイムアウト(`SoTimeout`)付きで`readLine()`し、`SocketTimeoutException`が飛ぶこと(＝何も返ってこないこと)を確認する設計にした。2クライアントで「相手には届くが自分には届かない」ことを個別に確認するよりも、この方法の方がブロードキャスト除外ロジックの欠落を確実に検出できる。
- ユーザー名ハンドシェイク直後にサーバーから当該クライアント本人へ「ようこそ」メッセージを直接送るプロトコルにした。テストではこのメッセージを読むことでサーバー側の登録完了を待ち合わせ、複数クライアントの接続順とブロードキーストタイミングの競合(レースコンディション)を避けている。
- 手動確認として、実際に`Main`(サーバー)と`ChatClientMain`(クライアント)を別プロセスで起動し、2クライアント間でのメッセージ相互送信・片方切断時の退出通知配信までコマンドラインから直接確認した。

### コードレビュー指摘への対応(Issue #158)
- **1接続の失敗でサーバー全体が停止していた問題**: `acceptLoop`の`catch (IOException) { break; }`が`stop()`によるクローズと個別クライアントの接続処理失敗を区別していなかった。`serverSocket.isClosed()`を見て、クローズによる例外のみループを終了し、それ以外は該当接続をスキップして受け付けを継続するよう修正した。
- **入室通知が本人にしか届かなかった問題**: 本人への「ようこそ」メッセージに加え、他の参加者へ`SERVER: <username>が入室しました`をブロードキャストするようにした。この変更により、複数クライアントを先に全部接続してから順にユーザー名を送るテストの書き方だと、まだ登録前のクライアントが他人の入室通知を受け取ってしまうレースが顕在化したため、既存テストは「1人ずつ接続→登録完了を待つ→次を接続」という順序に修正した。
- **`PrintWriter`の送信失敗を検知していなかった問題**: `ClientHandler.send()`で`checkError()`を確認し、失敗時は自ら接続をクローズするようにした。TCPの仕様上、実ソケットで書き込みエラーを確実に再現するのは難しい(送信バッファに乗って最初の1回は成功してしまうことが多い)ため、テストは「1接続がSO_LINGER(0)で異常切断されても、他クライアント間の通信が継続する」という統合的な振る舞いで検証した。
- **クライアント側がサーバー切断を検知しない問題**: `ChatClientMain`をテスト可能な`run(Socket, Scanner, PrintStream)`に分離した。受信スレッドがストリーム終端(サーバー切断)を検知したら「サーバーとの接続が切断されました」と表示し、送信ループも`checkError()`を確認して安全に終了するようにした(検知できないとハングし続ける)。テストは`PipedInputStream`で「ユーザーが入力を続けている状態」を再現し、サーバー停止後も複数回書き込みを試行することで送信エラーを確実に検知させている。
- **ユーザー名の重複・空文字・長さの検証がない問題**: `ClientHandler`で空文字・20文字超過・重複を検証し、該当する場合は拒否メッセージを送って接続を閉じる(参加者一覧には加えない)ようにした。
- **`ChatServer.port()`を`start()`前に呼ぶとNPEになる問題**: `serverSocket`が`null`の場合は`IllegalStateException`を分かりやすいメッセージで送出するようにした。
