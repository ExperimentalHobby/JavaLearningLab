# 迷路生成&探索ビジュアライザ(JavaFX)

## 学習ポイント
BFS/DFS/A*、Canvas描画、アニメーション

## 概要
再帰的バックトラック法で「完全迷路」(任意の2マス間の経路が一意に定まる迷路)を生成し、BFS/DFS/A*の3アルゴリズムで
スタート(左上・緑)からゴール(右下・赤)までの経路を探索、JavaFXの`Canvas`に経路をアニメーション表示するツール。
「迷路生成」ボタンで再生成、アルゴリズムを選択して「探索アニメーション開始」で経路が1マスずつ塗りつぶされていく。

## 実装メモ
- Issue #11/#18と同じ方針で、Canvas描画・アニメーション自体は自動テストが困難なため、`MazeGenerator`と各`MazeSolver`はJavaFXに依存しない純粋なロジックとしてTDDし、GUI(`MazeVisualizerApp`)は実装後に実機起動・スクリーンショットで手動確認した。
- 迷路は`Map<Cell, Set<Cell>>`で「通路として繋がっているマス」を表現した(壁の2次元配列ではなく接続グラフとして持つことで、生成・探索の両方をシンプルなグラフアルゴリズムとして実装できる)。
- `MazeGenerator`は`seed`付き`Random`で再帰的バックトラック法(スタック使用の反復版、深い再帰によるスタックオーバーフロー回避)を実装し、同じseedなら常に同じ迷路が生成されることをテストで保証した。再帰的バックトラック法は必ず全域木(スパニングツリー)を生成するため、任意の2マス間の経路が一意に定まり、BFS/DFS/A*はどれも同じ経路を返す(探索順序・訪問順は異なる)。
- ソルバーのテストは、生成された迷路ではなく手動で組み立てた小さな迷路(3マスの直線)を使い、アルゴリズムの実装そのものを検証した。到達不可能なケース(通路を繋がない2マス)では空リストを返すことも確認した。
- **JavaFXの既知の制約**: `main`メソッドを持つクラスが直接`javafx.application.Application`を継承していると、クラスパス実行時に「JavaFXランタイム・コンポーネントが不足しています」というエラーになった。`Application`サブクラス(`MazeVisualizerApp`)とエントリーポイント(`Main`、`Application.launch(MazeVisualizerApp.class, args)`を呼ぶだけ)を分離することで解決した。
- 依存関係のクラシファイアは開発機がWindows専用のため`win`に固定した(`javafx-controls`/`javafx-graphics` 24.0.1)。Java 25でもビルド・実行とも問題なく動作することを確認済み。
- 実機での手動確認では、通常のハードウェアアクセラレーション(Direct3D)描画だとスクリーンショット取得環境で画面キャプチャに描画内容が反映されなかったため、確認時のみ`-Dprism.order=sw`(ソフトウェアレンダリング)を指定して迷路描画・探索アニメーションが正しく動作することを確認した。通常の対話的環境では既定のハードウェアアクセラレーションで問題なく動作する想定。
