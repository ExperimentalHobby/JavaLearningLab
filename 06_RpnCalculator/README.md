# 簡易電卓(逆ポーランド記法)

## 学習ポイント
スタック(LIFO)構造の活用、パーサー実装

## 概要
逆ポーランド記法(RPN)の数式(例: `3 4 +`、べき乗は`2 10 ^`)を評価する対話式CLI電卓。数値は`BigDecimal`で厳密に計算する。`exit`で終了する。

## 実装メモ
- `Deque<BigDecimal>`(実装は`ArrayDeque`)にトークンを順次push/popすることでRPNを評価する。演算子が来たら直近2つの値をpopして計算し、結果を再度pushする。当初は`java.util.Stack`を使っていたが、`Vector`由来で全メソッドが同期化されたレガシークラスであるため、単一スレッドでの利用に同期コストが不要な`ArrayDeque`に置き換えた(`push`/`pop`/`peek`のシグネチャは同じため置き換えは最小限)。
- 01_Calculatorと同様、`0.1+0.2`のような誤差を避けるため`double`ではなく`BigDecimal`を使用。除算はスケール10・`RoundingMode.HALF_UP`で丸める。結果表示は`stripTrailingZeros().toPlainString()`で整形し、割り切れる除算でも`5.0000000000`のような表示にならないようにしている。
- パーサーとしての妥当性検証は3種類: ①数値でも演算子でもないトークン、②演算子適用時のオペランド不足、③評価終了時にスタックへ複数(または0個)の値が残る不正な式。いずれも`RpnCalculatorException`にまとめ、`Main`側で一律にエラー表示・継続できるようにした。
- べき乗演算子(`^`)に対応し、指数(スタックの2番目の値)が0以上の整数であることを検証した上で`BigDecimal.pow(int)`で計算する。単項マイナスは`"-5"`のような負数リテラルをパーサーがそのまま解釈できるため追加対応不要。中置記法からRPNへの変換(操車場アルゴリズム)は新規の大きな機能追加になるため、今回は見送り今後の拡張候補とした。
- `Main`は01〜05と同じ設計パターンで、Scanner/PrintStreamを引数に取る`run`静的メソッドに分離し、不正な式でクラッシュせず継続することを結合テストで検証した。
