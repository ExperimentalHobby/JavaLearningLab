# 簡易テキストエディタ(Swing)

## 学習ポイント
JTextArea、ファイル入出力、メニューバー

## 概要
`JTextArea`でテキストを編集し、メニューバーからファイルの「新規作成」「開く」「保存」「名前を付けて保存」「終了」、
編集の「元に戻す」「やり直す」(Undo/Redo)を行える簡易テキストエディタ。
「保存」は現在開いているファイルがあればそこへ上書き、なければ「名前を付けて保存」と同じ動作になる。
未保存の変更(タイトルバーに`*`で表示)がある状態で「新規作成」「開く」「終了」を行おうとすると、
破棄してよいか確認ダイアログが表示される。「名前を付けて保存」で既存ファイルを選ぶと上書き確認が入る。

## 実装メモ
- Issue #11(家計簿アプリ)と同じ方針で、テスト方針を明確に分離した: ファイルI/Oロジック(`TextFileService`)・文書の状態遷移(`EditorDocument`)はTDDで自動テストし、`TextEditorFrame`(実際のウィンドウ・メニューバー・イベントリスナー配線)は実装後に実機で起動して手動確認した。
- `TextFileService`は`Files.readString`/`Files.writeString`(UTF-8)を使い、GUIに依存しない純粋なロジックとして`@TempDir`の実ファイルでテストした。読み込み/書き込みの失敗(存在しないファイル・存在しないディレクトリなど)は`TextFileException`に統一している。UTF-8として不正なバイト列(例: Shift_JISで保存されたファイル)は`MalformedInputException`を個別に捕捉し、「ファイルの読み込みに失敗しました」だけでは原因が分からなかった問題に対応して、文字コードが原因である可能性を示すメッセージにしている。
- `EditorDocument`にdirtyフラグ(`markDirty()`/`isDirty()`)を追加した。`open`/`save`/`saveAs`/`newDocument`でクリアされ、`TextEditorFrame`が`JTextArea`の`DocumentListener`でテキスト変更を検知するたびに`markDirty()`を呼ぶ。「開く」やウィンドウを閉じる操作の前に未保存の変更を確認せず失われていた問題、タイトルバーに変更マーク(`*`)が出ない問題、「新規作成」メニューがなく「無題」状態に戻せない問題への対応。
- `TextEditorFrame`は`JMenuBar`の「ファイル」メニューに新規作成/開く/保存/名前を付けて保存/終了の`JMenuItem`をラムダの`ActionListener`で配線した。「開く」「名前を付けて保存」は`JFileChooser`でパス選択し、選択したファイル名をウィンドウタイトルに反映する。「名前を付けて保存」は選択先が既存ファイルの場合`JOptionPane`で明示的な上書き確認を挟む(`JFileChooser`の既定は上書き確認をしないため)。失敗時は`JOptionPane`でエラーダイアログを表示する。
- 「編集」メニューに`javax.swing.undo.UndoManager`を使ったUndo/Redo(`元に戻す`/`やり直す`、`Ctrl+Z`/`Ctrl+Y`)を追加した。検索・置換は新規ダイアログの実装を要する大きめのUI追加になるため、今回は見送り今後の拡張候補とした。
- 手動確認では、実際にWindows上でアプリを起動し、テキスト入力→「名前を付けて保存」でのファイル書き込み→タイトルバー更新→「開く」での再読み込みの一連の流れをスクリーンショットで検証した。ファイルシステム上でも保存内容が期待通りであることを確認済み。
