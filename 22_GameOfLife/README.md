# ライフゲーム(Conway's Game of Life)

## 学習ポイント
2D配列操作、GUI描画、タイマー駆動更新

## 概要
Conwayのライフゲームを、`javax.swing.Timer`で世代更新しながらグリッドを描画するSwing GUIアプリ。
マス目をクリックして初期パターンを編集し、「開始」「停止」「1世代進める」「クリア」「ランダム生成」ボタンで操作する。
定番パターン(グライダー・ブリンカー・トード)のプリセット配置、速度調整、トーラスモード(端のラップアラウンド)の切り替えにも対応する。

## 実装メモ
- Issue #11/#18/#21と同じ方針で、`Grid`/`GameOfLife`はGUIに依存しない純粋なロジックとしてTDDし、`LifeFrame`は実装後に実機起動・スクリーンショットで手動確認した。
- `Grid`は`boolean[][]`の2次元配列で盤面を表現し、`countLiveNeighbors`は境界外を非生存として扱う(トーラス状のラップアラウンドはしない、盤面の端では隣接マスが少なくカウントされる仕様)。
- `GameOfLife.nextGeneration`は現在の`Grid`を書き換えず新しい`Grid`を返す純粋関数とした。世代更新中に元の盤面を参照しながら判定する必要があるため、インプレース更新だと参照している最中に値が変わってしまう不整合を避けられる。
- ソルバーのテストでは、既知の周期パターン「ブリンカー」(3マスの直線が1世代ごとに90度回転する)を使い、隣接セル数だけでなく実際のパターン変化まで含めて`nextGeneration`の正しさを検証した。
- `LifeFrame`は`javax.swing.Timer`で一定間隔(150ms)ごとに世代を進める「タイマー駆動更新」を実装した。フレームワーク指定のない学習ポイントだったため、既存exercise(#11/#18)と同じSwingを採用し、新規依存関係を増やさずに済ませた。
- 手動確認では、実際にWindows上でアプリを起動し、「ランダム生成」で初期パターンを作成→「開始」でタイマーが自動的に世代を進める(2秒間で13世代)ことをスクリーンショットで確認した。

### コードレビュー指摘への対応(Issue #156)
- **プリセットがない問題**: `Preset` enum(GLIDER/BLINKER/TOAD)と`LifeBoardState.loadPreset(Preset)`を追加し、GUIのプリセット選択+「プリセット配置」ボタンでワンクリック配置できるようにした。**盤面の保存/読込はファイルI/O+専用UIが必要でスコープが大きいため見送り**、将来課題とする。
- **速度調整・盤面サイズ変更ができない問題**: GUIに速度セレクタ(遅い/普通/速い、`Timer.setDelay`に連動)を追加した。**盤面サイズ変更は`LifeBoardState`とキャンバスの再構築を伴い影響範囲が大きいため見送り**、将来課題とする。
- **安定状態・振動検出による自動停止がない問題**: `Grid`に`equals`/`hashCode`を追加し、`LifeBoardState`が直近10世代の履歴と比較、同一盤面が現れたら`isStable()`がtrueを返すようにした。`LifeFrame`はこれを検知するとタイマーを自動停止し「安定状態のため停止しました」と表示する。
- **`Grid.isAlive`/`setAlive`の範囲外チェックがない問題**: 配列アクセスに任せると`ArrayIndexOutOfBoundsException`になっていたが、明示的な検証で`IllegalArgumentException`を送出するようにした。
- **実行中クリックが即座に上書きされる問題**: `LifeBoardState`に`running`状態を追加し、実行中は`toggleCell`を無視するようにした。`LifeFrame`の「開始」「停止」ボタンと連動させている。
- **学習テーマ「トーラスモードの切り替えがない」への対応**: `Grid.countLiveNeighbors(row, col, wrapAround)`をオーバーロードとして追加し、`GameOfLife.nextGeneration(grid, wrapAround)`経由で`LifeBoardState.setTorusMode()`から切り替え可能にした。GUIには「トーラスモード」チェックボックスを追加した。
